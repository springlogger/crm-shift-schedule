# График смен

Редактор графика смен: сотрудники по строкам, дни по колонкам. Смены назначаются шаблоном, своим временем, на всю дату сразу или перетаскиванием. Черновик сохраняется на сервер и публикуется.

**Стек:** Laravel 13 (PHP 8.4) · Vue 3 + TypeScript · Pinia · TanStack Vue Query · Tailwind v4 · Vite+ (Vite, Oxlint, Oxfmt, Vitest).

## Запуск

Нужны PHP 8.3+ с Composer и Node.js 22+. На Windows проще всего поставить PHP и Composer через [Laravel Herd](https://herd.laravel.com) или [php.new](https://php.new).

```bash
git clone https://github.com/springlogger/crm-shift-schedule.git
cd crm-shift-schedule

composer install
cp .env.example .env
php artisan key:generate

touch database/database.sqlite      # по умолчанию SQLite, отдельная БД не нужна
php artisan migrate --seed          # 8 сотрудников, 3 шаблона, демо-смены на текущую неделю

npm install
composer run dev                    # Laravel + Vite одной командой
```

Откройте <http://localhost:8000/schedule>.

Без dev-сервера Vite:

```bash
npm run build
php artisan serve
```

Если страница пустая и в консоли ошибки загрузки с `:5173`, остался файл `public/hot` от прошлого `npm run dev`. Удалите его или запустите `composer run dev`.

Сбросить данные к демо-состоянию: `php artisan migrate:fresh --seed`.

## Как пользоваться

Ниже описано, что должно происходить, поэтому этот раздел можно использовать и как чек-лист для ручной проверки.

### Выделение ячеек

| Действие | Результат |
|---|---|
| Клик по ячейке | выделяется одна ячейка, предыдущее выделение снимается |
| Нажать и протянуть мышью | выделяется прямоугольник ячеек |
| **Ctrl** (⌘ на Mac) + клик или протягивание | ячейки добавляются к выделению; если начать с уже выделенной ячейки, она снимается |
| **Shift** + клик | выделяется диапазон от предыдущей ячейки до этой |
| Tab по ячейкам, затем Enter или пробел | выделение с клавиатуры |
| **Esc** или «Снять выделение» | выделение сбрасывается |

Пока что-то выделено, над таблицей вместо поиска стоит тёмная плашка «Выделено: N ячеек · M сотрудников · K дн.». Высота шапки при этом не меняется, и таблица не прыгает.

### Назначение смен

- **Шаблон.** Выделите ячейки и кликните по шаблону справа (Утро, День, Вечер) или нажмите его цифру **1–9**. Во все выделенные ячейки встанет смена этого шаблона. Если ничего не выделено, появится подсказка.
- **Своя смена.** Выделите ячейки, введите начало и конец (только цифры, двоеточие подставится само) и нажмите «Поставить в выделенное». Кнопка неактивна, пока время некорректно или совпадают начало и конец. Смена через полночь (22:00–06:00) допустима и считается как 8 ч.
- **Вся дата сразу.** Клик по дате в шапке таблицы («вт 3») открывает меню шаблонов. Выбранный шаблон ставится всем видимым сотрудникам, у которых в этот день ещё нет смены.
- **Перетаскивание.**
  - Шаблон из правой панели на ячейку — назначается в неё. Если ячейка входит в выделение, то во всё выделение.
  - Смену с одной ячейки на другую — переносится; с зажатым **Alt** или **Ctrl** — копируется.
- **Очистить.** «Очистить смены» на плашке или **Delete** удаляют смены в выделенных ячейках.
- **Отменить / повторить.** Кнопки ↶ ↷ рядом с «Сохранить» или **Ctrl+Z** / **Ctrl+Shift+Z** (**Ctrl+Y**).

Хоткеи работают и в русской раскладке. Пока курсор в поле ввода, работает только **Ctrl+S**.

### Что пересчитывается сразу

- **Покрытие** (нижняя строка) — сколько человек на смене в этот день. 0 подсвечивается красным, больше 0 — синим. Считаются все сотрудники, даже скрытые поиском.
- **Часы у сотрудника** — «назначено / норма» за показанный период. Норма недельная, за месяц она считается пропорционально числу дней. Переработка подсвечивается красным.

### Период и поиск

- **Неделя / Месяц** переключают вид. В месяце ячейки уже, и чип показывает только длительность; полное время видно во всплывающей подсказке.
- Стрелки листают период, «Сегодня» возвращает к текущему. Соседние периоды подгружаются заранее, поэтому листание идёт без лоадера.
- **Поиск по ФИО**: нечёткий, по части имени или фамилии в любом порядке («алин кузн»), «е» и «ё» не различаются. Если никого не нашлось, показывается отдельное сообщение.
- Период и поиск хранятся в адресе (`?view=week&date=2026-11-02&q=алина`): после перезагрузки откроется то же место.

### Сохранение и публикация

- Все правки — черновик в браузере. Пока они не сохранены, рядом с кнопками горит «Есть несохранённые изменения». Если вручную вернуть всё как было, надпись гаснет.
- **Сохранить** (или **Ctrl+S**) отправляет период на сервер. Изменённые смены становятся черновиком, бейдж у заголовка показывает «Черновик».
- **Опубликовать** переводит смены периода в опубликованные, бейдж меняется на «Опубликован». Если есть несохранённые правки, они сначала сохраняются.
- Перед сменой периода или вида, уходом со страницы или закрытием вкладки с несохранёнными правками приложение спросит подтверждение.
- Ошибки сервера (например, валидации) показываются тостом справа внизу.

## Архитектура

Один Laravel-проект. Vue SPA лежит в `resources/js`, Blade используется только как оболочка (`routes/web.php` → `app.blade.php`). Фронт общается с бэком через JSON API `/api/*`, так что граница между ними проходит по API, а не размыта Inertia. Сессия и CSRF общие с SPA через Sanctum `statefulApi()`, CORS не нужен.

```
app/
├─ Enums/                  ShiftStatus, ShiftColor
├─ Models/                 Employee, ShiftTemplate, Shift
├─ Http/Controllers/Api/   тонкие контроллеры
├─ Http/Requests/          PeriodRequest, SyncShiftsRequest, EmployeeIndexRequest
├─ Http/Resources/         camelCase-ответы ровно под типы фронта
└─ Services/ShiftSyncService.php   diff и транзакция

resources/js/              Feature-Sliced Design
├─ app/                    точка входа, роутер
├─ pages/schedule/         связывает данные, черновик, выделение, хоткеи
├─ widgets/                schedule-grid, shift-panel, selection-bar
├─ features/               cell-selection, shift-dnd, period-navigation, employee-search, custom-shift
├─ entities/               employee, shift (store, API), shift-template
└─ shared/                 ui-кит, api-клиент, lib (время, даты)
```

### API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/employees?search=` | список сотрудников; поиск по словам в фамилии и имени |
| GET | `/api/shift-templates` | шаблоны смен |
| GET | `/api/shifts?from=&to=` | смены периода (не длиннее 62 дней) |
| PUT | `/api/shifts/sync` | `{from, to, shifts[]}`: полная замена смен периода |
| POST | `/api/shifts/publish` | `{from, to}`: перевод смен периода в `published` |

Ошибки валидации приходят в стандартном формате Laravel `422 {message, errors}` с русскими текстами.

### Почему `sync` целым периодом, а не CRUD по смене

В интерфейсе есть «Сохранить»: пользователь правит черновик локально и сохраняет пачкой. За месяц это максимум `сотрудники × 31` записей, поэтому гонять полный список нормально. `ShiftSyncService` в одной транзакции сравнивает присланное с БД:

- в БД есть, в запросе нет → удалить;
- в запросе есть, в БД нет → вставить черновиком;
- есть и там, и там, но отличается → обновить и вернуть в черновик;
- совпадает → не трогать, статус `published` сохраняется.

Валидация не ставит `exists` на каждый элемент, потому что это был бы отдельный SQL-запрос на каждую смену. Все id проверяются двумя `whereIn` в `after()`, там же ловятся дубликаты «сотрудник + день» внутри запроса.

### Состояние на фронте

- **Vue Query** хранит то, что лежит на сервере: кэш по ключу `['shifts', from, to]`, `staleTime` одна минута, префетч соседних периодов. После сохранения ответ кладётся прямо в кэш, лишнего GET нет. Остальные периоды помечаются устаревшими, потому что неделя и месяц пересекаются.
- **Pinia** (`entities/shift/model/store.ts`) хранит черновик. Смены лежат в `Map<"employeeId:date", Shift>`, и ячейка находит свою смену за O(1), а не перебором массива. Каждая правка создаёт новую `Map`, поэтому undo/redo (`useManualRefHistory`) работает без глубокого клонирования. Покрытие, часы и `isDirty` считаются через computed.
- **Выделение** живёт в отдельном composable, а не в store смен, чтобы undo не откатывало выделение.
- **Бэк** кэширует справочники (`Cache::rememberForever`) и сбрасывает кэш в `booted()` модели. В кэше лежат сырые строки, а модели собираются через `hydrate()`, потому что Laravel по умолчанию не десериализует объекты из кэша (`cache.serializable_classes = false`). Смены не кэшируются: они меняются постоянно, а инвалидация по пересекающимся периодам добавила бы больше багов, чем пользы.

## Решения и допущения

1. **Одна смена на сотрудника в день:** `UNIQUE(employee_id, date)`. На этот же индекс опирается `upsert`.
2. **Время копируется из шаблона в смену.** `shift_template_id` нужен только для цвета. Если поменять шаблон, уже назначенные смены не изменятся. При удалении шаблона смены остаются «своими» (`nullOnDelete`).
3. **Ночные смены** (22:00–06:00) считаются с переходом через полночь и принадлежат дате начала. Смена с совпадающими началом и концом запрещена и на фронте, и на бэке.
4. **Длительность — чистая разница без перерыва.** В макете у «Вечер 15:00–23:00» указано 9 ч, хотя разница 8 ч. Я считаю, что это опечатка, и показываю 8 ч.
5. **Даты — строки `YYYY-MM-DD`** везде, и в БД, и на фронте. `new Date('2026-11-02')` парсится как UTC-полночь и западнее Гринвича уезжает на день назад. У `Shift` колонка `date` нарочно не кастуется в Carbon: иначе Eloquent записал бы в SQLite `Y-m-d H:i:s`, и `whereBetween` по строкам терял бы последний день периода.
6. **Покрытие считается по всем сотрудникам**, а не только по найденным поиском: оно описывает график, а не то, что сейчас на экране.
7. **Назначение по дате ставит смену только свободным**, чтобы не затирать уже назначенное. Если нужно перезаписать, выделите колонку протягиванием.
8. **Авторизации нет**, её не просили. CSRF для SPA работает через Sanctum (запрос без токена с домена приложения получает 419), но API открыт и для внешних клиентов, и сюда первым делом добавилась бы авторизация.
9. **Только десктоп:** нативный DnD и выделение через `pointerenter` рассчитаны на мышь. Протягивание засчитывается после сдвига мыши хотя бы на 4 px, поэтому сдвиг вёрстки под неподвижным курсором не расширяет выделение.
10. Серверный поиск `?search=` работает, но фронту хватает клиентского. В SQLite `LIKE` регистронезависим только для латиницы, на MySQL/PostgreSQL это не проблема.

## Что сделал бы дальше

- Сущность `schedules` (список графиков, на который ведёт «← Графики смен»), чтобы публиковать именованный график, а не диапазон дат.
- Оптимистичную блокировку: сейчас при одновременном редактировании побеждает последний сохранивший.
- Виртуализацию строк (`@tanstack/vue-virtual`), если сотрудников станет больше пары сотен.
- E2E на Playwright и OpenAPI-документацию (`dedoc/scramble`).
